## 5070ti 클럭고정 베이스라인 추론 실험

### 실험 개요
- 목적: GPU 클럭/PCIe 최대 고정 후 추론 성능 변화 측정
- 클럭 고정 명령:
  - `nvidia-smi -pm 1` (Persistence mode)
  - `nvidia-smi -lgc 3090,3090` (Graphics clock lock)
  - `nvidia-smi -lmc 14001,14001` (Memory clock lock)
  - `nvidia-smi -pl 300` (Power limit 300W)
- 스크립트: `research/R1-5070ti/baseline/baseline_maxclock.py`

### 클럭 고정 확인
| 항목 | 기본 (아이들) | 클럭 고정 후 |
|------|--------------|-------------|
| Graphics Clock | 180 MHz (P8) | **2842 MHz (P0)** |
| Memory Clock | 405 MHz | **14001 MHz** |
| PCIe | Gen1 x16 | **Gen5 x16** |
| Performance State | P8 | **P0** |
| Power Limit | 300W | 300W |

- Blackwell 아키텍처 (RTX 5070 Ti): `-lgc`, `-lmc` 명령 정상 동작 확인
- Graphics는 3090 MHz 요청이지만 실측 2842 MHz (부스트 범위 내 정상)

### 기본 vs 클럭고정 비교
| 항목 | 기본 (P8→P0) | 클럭고정 (P0) | 개선 |
|------|-------------|-------------|------|
| 추론 시간 | 184.99s | **168.95s** | **-8.7% (1.09x)** |
| 모델 로드 | 53.17s | 52.09s | -2.0% |
| Peak VRAM | 13.66 GB | 13.66 GB | 동일 |
| minADE | 2.5548m | 2.5548m | 동일 (재현성 확인) |

### 분석
- 클럭 고정으로 추론 시간 약 9% 개선 (184.99s → 168.95s)
- VRAM 사용량 동일 — 클럭이 병목이 아닌 CPU-GPU 통신(오프로드) 병목 확인
- device_map="auto" device placement: CUDA 29, CPU 17 (기본 실험의 649/510과 다름 — 실험 간 환경 차이)
- minADE 동일 → 재현성 확보

### 핵심 인사이트
- PCIe Gen5 x16 환경에서도 CPU 오프로드 레이어가 병목
- 클럭 자체보다 레이어 배치 최적화가 중요
- 5070 Ti (Gen5) vs 3080 Ti (Gen3) 비교: 5070 Ti가 오히려 느린 것은 CPU 오프로드 방식 차이

## 5070ti Pinned Memory On-Demand Layering 실험

### 실험 개요
- 목적: CPU 오프로드 레이어를 pin_memory()로 고정하여 H2D DMA 전송 활용
- 비교 대상: 베이스라인 (device_map=auto, 184.99s)
- 스크립트: `research/R1-5070ti/pinned-memory/pinned_memory_inference.py`

### 실험 방법
1. 모델을 CPU FP16으로 로드 (38.39s)
2. Non-VLM 컴포넌트 + 상위 VLM 레이어 11개 → GPU
3. 하위 VLM 레이어 25개 → CPU
4. CPU 레이어를 `pin_memory()`로 변환 (DMA 전송용)
5. Forward hook: pinned CPU → GPU (H2D, non_blocking=True) → Free (D2H 없음)

### 최종 결과
| 항목 | 값 |
|------|-----|
| 방식 | Pinned Memory On-Demand Layering |
| GPU | RTX 5070 Ti 16GB |
| CPU 로드 | 38.39s |
| Setup (오프로드+핀닝) | 64.09s |
| **추론 시간** | **61.27s** |
| **베이스라인 대비** | **3.02x 향상** |
| Peak VRAM | 12.76 GB |
| H2D 평균 | 47.52 ms/layer |
| FREE 평균 | 11.46 ms/layer |
| Pin time | 44.45s |
| minADE | 2.5548m (정확도 유지) |
| H2D 총 횟수 | 550회 |

### 추론 시간 분해
| 단계 | 시간 | 비율 |
|------|------|------|
| H2D 전송 | 26.14s | 42.7% |
| FREE (GPU 해제) | 6.31s | 10.3% |
| 연산 | 28.82s | 47.0% |

### 비교 테이블 (5070 Ti)
| 방식 | 추론 시간 | 속도향상 | Peak VRAM |
|------|-----------|---------|-----------|
| Baseline (device_map=auto) | 184.99s | 1.0x | 13.66 GB |
| Max Clock Baseline | 168.95s | 1.09x | 13.66 GB |
| **Pinned Memory On-Demand** | **61.27s** | **3.02x** | **12.76 GB** |

### 핵심 분석
- **PCIe Gen5 x16** 환경에서 H2D 47.52ms/layer (WSL2 Gen3에서 측정 불가 비교)
- Pinned Memory: DMA 직접 전송으로 일반 pageable memory 대비 빠름
- H2D가 전체 추론의 42.7% 차지 → 추가 최적화 여지 있음
- D2H 없음 → FREE 단계는 포인터 교체 + cache clear만 (11.46ms)
- minADE 2.5548m → 베이스라인과 동일, 정확도 손실 없음

### 트러블슈팅 내역
1. **Direct CUDA 생성 OOM**: `torch.set_default_device("cuda")`로 전체 모델 CUDA 생성 시 15.5GB 초과
2. **action_in_proj CPU 잔류**: expert_decoder를 GPU로 이동했지만 action_in_proj 누락 → 추가
3. **NUM_OFFLOAD 조정**: 17개로는 추론 중 VRAM 14.94GB → OOM, 25개로 12.76GB 안정
